**Release candidate 3 for 0.6.0: the composer keeps what you type, arranging without scripts, and guards against edits landing in the wrong project.** Everything from v0.6.0-rc.2, plus the changes below.

### Install
Install `Hibiki-0.6.0-rc.3.pkg` (macOS) or `Hibiki-0.6.0-rc.3-setup.exe` (Windows) over v0.5.x or an earlier 0.6.0 candidate, then restart REAPER so the new bridge and panel load. `hibiki doctor` should show `0.6.0-rc.3`. Installing a package switches the machine back to release mode.

### New
- **Arranging tools**: `item` can `split` at beats, `delete` and `duplicate` items (the copy is independent, not pooled), trim or extend an item's start with `left_edge_beats` (the audio stays in place), move an item to another track, switch the active take and set fade shapes. Item lists show the take name, source file and number of takes.
- **Envelope ranges**: `envelope get` and `set` take `start_beats` / `end_beats`, so one passage of a long automation lane can be read or rewritten without touching the rest.
- **What you have selected**: `status` always reports the time selection, the selected tracks and items, and the cursor in beats. `status detail=true` lists tempo and meter changes.
- **Go to a bar or marker**: `transport goto` moves the edit cursor (and playback, when playing) to a beat or to a marker or region by number or name.
- **Render formats**: `render` takes `format` `wav` (16-bit, 24-bit or 32-bit float) or `mp3` (320 kbps) for one render; the project's own render format comes back afterwards.
- `midi get_cc` reads CC, program changes and pitch bend. `fx params` takes a name `filter`. `batch` takes `stop_on_error`.

### Changed
- **One reply, one project**: a reply now works on the project tab that was in front when it first changed something. If another tab comes to the front, its edits and renders are refused instead of landing there. From the panel this holds until the reply ends; for other MCP clients the first refusal follows the new tab.
- **`run_lua` timeouts stop the script**: a snippet still running Lua after its `timeout` (default 10 s) is stopped with an error. A call blocked inside REAPER, such as a render or a dialog, still can't be interrupted.
- **Renamed fields**: `item` uses `fade_in_sec` / `fade_out_sec` (was `fade_in` / `fade_out`); `transport` returns `position_sec` and `position_beats` (was `position`).
- Files attached for a Gamut agent also list their path on the REAPER machine, so the agent can import them.
- The panel is now four files (`Hibiki.lua`, `context.lua`, `markdown.lua`, `studio.lua`); the installer places all of them.

### Fixed
- **Typed text disappeared** when you clicked anywhere outside the message box (the Context switch, + File, an attachment, the conversation) before sending. The text now stays.
- **Pressing Enter to commit a pinyin composition sent the message.** It now only commits the letters.
- After that commit the cursor sat one character before the end.
- **Audition rack**: Keep on a variant made of several tracks now keeps all of them.
- **Two REAPER instances** could both pick up the same request. The second REAPER now waits until the first one quits, and each request runs once.
- Windows kept every version-history snapshot; it now keeps the newest 200, as macOS does.

### Known
- Apple's `DLSMusicDevice` crashes playback when more than one instance runs in a project. Keep one, or set the others offline.
- Version-history pruning on Windows is covered by review, not yet tried on a desktop.
- Signing and notarization of the installers are still to come.

### Upgrading
Install over v0.5.x or an earlier 0.6.0 candidate. Scripts that pass `fade_in` / `fade_out` to `item update` or read `position` from `transport` need the new names. If you were in dev mode, the installer switches you back to this release.
